= Software design

Software design is concerned with how you assemble lines of code. It is concerned with the structure
of classes, functions, and modules within a single codebase, and the decisions that shape how they
fit together.

Software design is distinct from xref:system-design.adoc[*system design*], which is concerned with
how you assemble services. System design is about the structure of a *distributed system's*
components, interfaces, and data across process and network boundaries.

Software design is closely related to xref:software-architecture.adoc[*software architecture*].
The commonly-cited distinction is that architecture is concerned with design decisions that are
expensive to change later. Architectural decisions include how services are partitioned and how
data is distributed. Software design is more local and recoverable. However, the two concepts sit
on a spectrum with no clear boundary between them, and the two terms are often used interchangeably.
xref:high-level-design.adoc[*High-level design*] and *low-level design* are sometimes uses as
synonyms.

Within a single codebase, software design plays out through xref:design-principles.adoc[*design principles*]
such as preferring xref:cohesion.adoc[*cohesion*] over xref:coupling.adoc[*coupling*], and through use
of reusable xref:design-patterns.adoc[*design patterns*] that solve recurring structural problems.
xref:modular-design.adoc[*Modular design*] – organizing code into self-contained modules with narrow
public interfaces – is one of the central concerns of software design.
