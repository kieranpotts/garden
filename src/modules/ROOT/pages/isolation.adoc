= Isolation

Isolation is a design principle that aims to improve the xref:resilience.adoc[*resilience*] of IT
systems, especially *[distributed]* ones.

The idea is, if you have a failure in one part of a system, you want to reduce the blast radius by
isolating the failure so it does not cascade into other parts.

There are many mechanisms for isolation, and they can be applied at different levels of the system,
such as the network, the runtime environment, or the communication patterns. For example,
xref:firewalls.adoc[*firewalls*] can be used to prevent unauthorized access to a network, and
xref:virtual-machine.adoc[*virtual machines*] or xref:container.adoc[*containers*] can be used to
ensure that one service does not consume all the resources of the host machine.
xref:inter-process-communication.adoc[*Inter-process communication*] patterns such as
xref:message-queues.adoc[*message queues*] build isolation into the communication patterns, while
patterns such as xref:circuit-breaker.adoc[*circuit breakers*] and xref:bulkhead.adoc[*bulkheads*]
can be used to improve failure isolation between more tightly coupled services, while
xref:cell-based-architecture.adoc[*cell-based architecture*] applies the same principle at the scale
of a whole system, and xref:multi-tenant.adoc[*multi-tenant*] systems apply it at the boundary
between customers who share the same infrastructure.

See also xref:redundancy.adoc[*redundancy*], which is a complementary design principle.
