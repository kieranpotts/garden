= Security

:link-rmias: https://dl.acm.org/doi/10.1109/ARES.2013.72

*Security* in software engineering is the discipline of protecting systems and data from unauthorized access, damage, or disruption. It is usually treated as a xref:non-functional-requirements.adoc[*non-functional requirement*] and a xref:quality-attribute.adoc[*quality attribute*] — a condition the system must satisfy, rather than a feature it provides.

The conventional framing is the *CIA triad* — *confidentiality*, *integrity*, and xref:availability.adoc[*availability*]. Confidentiality limits who can read data. Integrity ensures data and behavior are not altered improperly. Availability ensures the system remains reachable when needed. Most security controls map onto one or more of these axes, and debates about priorities are often debates about which leg of the triad matters most for a given system.

The {link-rmias}[Reference Model of Information Assurance and Security (RMIAS)] extends the CIA triad with additional properties: xref:accountability.adoc[*accountability*], *auditability*, xref:authenticity.adoc[*authenticity*], and xref:non-repudiation.adoc[*non-repudiation*]. ISO/IEC 25010 frames security in similar terms, as a quality attribute composed of *confidentiality*, *integrity*, *non-repudiation*, *accountability*, and *authenticity*.

Technical controls such as xref:authentication.adoc[*authentication*], xref:authorization.adoc[*authorization*], xref:encryption.adoc[*encryption*], and xref:firewall.adoc[*firewalls*] are the most visible forms of security controls. xref:cryptography.adoc[*Cryptography*] is the mathematical foundation for many security control. Effectiveness of security controls is verified through xref:security-testing.adoc[*security testing*] and xref:penetration-testing.adoc[*penetration testing*].

Besides technical control security encompasses procedural and operational controls — eg. access policy, patching, audit, and incident response — and the xref:compliance.adoc[*compliance*] regimes that make those obligations enforceable.

Security is often conflated with xref:privacy.adoc[*privacy*]. The two are distinct. Security protects data from unauthorized access. Privacy governs what data is collected, how it is used, and on what basis. Good security is necessary for privacy, but is not sufficient on its own. A system can be secure and still be invasive in how it uses *personally identifiable information*.

Modern security practice favors xref:secure-by-design.adoc[*secure-by-design*], in which security is built in to systems frm outset, rather than retrofitting at the end of construction. Priorities are informed by community catalogs such as the xref:owasp.adoc[*OWASP Top 10*], which account for most real-world breaches and enumerate the risks associated with each type.
