= Software 3.0

:link-karpathy-software-2: https://karpathy.medium.com/software-2-0-a64152b37c35
:link-latent-space-s3:     https://www.latent.space/p/s3
:link-yegge-survival:      https://steve-yegge.medium.com/software-survival-3-0-97a2a6255f7b

*Software 3.0* is Andrej Karpathy's name for software programmed in natural language. A xref:prompt.adoc[*prompt*] is the program, and a xref:large-language-model.adoc[*large language model (LLM)*] is the computer that runs it. Karpathy set out the idea in a June 2025 talk, _Software Is Changing (Again)_, at Y Combinator's AI Startup School, building on his earlier quip that "the hottest new programming language is English."

== Three paradigms

Karpathy frames Software 3.0 as the third of three ways to program a computer.

* *Software 1.0.* Code written by hand, in a language such as C++ or Python, that tells the computer explicitly what to do.

* *Software 2.0.* The weights of a neural network. Nobody writes them directly. A programmer curates a dataset and sketches an architecture, and optimization searches for the program. Karpathy coined the term in a 2017 essay, drawing on his work at Tesla, where xref:machine-learning.adoc[*machine learning*] models progressively displaced hand-written code.

* *Software 3.0.* Prompts in English, which program an LLM, itself a Software 2.0 artifact, to behave as the application needs.

The three coexist, and each suits some jobs better than the others. Karpathy's central thesis is that, with the emergence of Software 3.0 "a huge amount of software will be rewritten." Because the programming language is English, almost anyone can now program, which is the phenomenon behind xref:vibe-coding.adoc[*vibe coding*].

== Software survival

Steve Yegge's 2026 essay _Software Survival 3.0_ asks what Software 3.0 does to the software that already exists. When agents can synthesize almost any functionality on demand, the binding constraints become tokens, compute, energy, and money, and those constraints act as selection pressure. An existing classical software tool competes not only with its competing software tools, but also with the option of having an agent build and operate a bespoke replacement.

Yegge's central thesis is that a classical software tool will survive if it saves an agent more tokens than the agent spends finding, learning, and using the tool. He predicts that winners will be tools that compress hard-won insight or run more cheaply than inference, such as Git, PostgreSQL, and xref:unix-philosophy.adoc[*Unix*] command-line tools. The losers are thin products that do work that an agent can now do directly and better, such as Stack Overflow, low-code platforms, and many categories of xref:software-as-a-service.adoc[*software-as-a-service*].
